Prueba local de voz

El audio viaja por WebRTC entre este navegador y ChatGPT Web. El puente local prepara el contexto y negocia la conexión sin entregar la credencial de ChatGPT al navegador.

Conexión
El modelo elegido se usa para el texto inicial. ChatGPT decide el modelo de voz según la cuenta y su disponibilidad.
Los adjuntos se envían al mismo chat. El archivo de audio de abajo es la fuente de voz, no un adjunto.
El archivo se reproduce hacia el canal en tiempo real; no se sube al servidor como adjunto.

Prueba local SIP/RTP paso a paso

El flujo principal está en el wrapper Bridge Console, dentro de Test Lab. Desde esta página heredada puedes lanzar el gateway Docker y conectar un cliente SIP local. Requiere una cuenta ChatGPT configurada en el puente.

1. En la terminal A, desde la raíz del repositorio, inicia el gateway. Docker toma la clave, la URL del puente y los puertos por defecto:

docker compose run --rm --build --service-ports sip-gateway

2. Configura MicroSIP con servidor 127.0.0.1, usuario voice, UDP 5060, sin clave; desactiva STUN/SRTP y habilita PCMU.

3. Para validar transporte automáticamente, ejecuta el cliente de prueba (mantén abierto el gateway):

uv run --extra sip python scripts/sip_rtp_smoke.py

Para probar voz reconocible en lugar del tono de transporte, pasa un WAV PCM hablado corto: uv run --extra sip python scripts/sip_rtp_smoke.py --wav "C:\\ruta\\audio.wav".

Resultado esperado: SIP INVITE 200 OK, paquetes RTP recibidos y SIP BYE 200. El tono puede recibir silencio y aun así validar transporte; para validar una respuesta de voz, usa WAV hablado y confirma que el pico PCM sea mayor que cero. Con Ctrl+C se detiene el gateway. Los detalles y límites están en docs/VOICE_TRANSPORT.md.
